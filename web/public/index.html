        How Forge learns a new skill

        1. Understand. The model reads your request and picks one of the verified live sources below, or says no if it needs a login, payment or private data.
        2. Look. It calls that source's real API and reads the actual response, so the code is written against real data, not guesses.
        3. Write. It writes a small JavaScript skill: one function that takes your inputs (a city, an amount…) and returns a spoken answer.
        4. Test, live. The skill runs in a sandbox, a container with no network of its own. Each request goes through Forge, which allows only the sites the skill declared and blocks private addresses. The test uses your own example, with real data.
        5. Cross-check. For sources marked ✓ below, Forge's own trusted reference reads the same values from the source (a temperature, a rate, today's headlines); the answer must match them. Anything that fails is repaired and retried, up to 4 attempts, or it is not kept.
        6. Your OK. You see what it does, its test result and every site it can reach. It is installed only if you say yes, and every answer cites its source.

        Where real-time data comes from

        Every answer is fetched live from the source when you ask. A repeat within 10 minutes reuses the source's last reply; if a source is down, I say how old the answer is (2 hours at most). ✓ means its answers are cross-checked.
