        How Forge learns a new skill

        1. Understand. The model reads your request and picks one of the verified live sources below, or says no if it needs a login, payment or private data.
        2. Look. It calls that source's real API and reads the actual response, so the code is written against real data, not guesses.
        3. Write. It writes a small JavaScript skill: one function that takes your inputs (a city, an amount…) and returns a spoken answer. Code that passed before for the same kind of skill is reused instead, and tested again.
        4. Test, live. The skill runs in a sandbox, a container with no network of its own. Each request goes through Forge, which allows only the sites the skill declared and blocks private addresses. It is tested with your own question, and again with different values so nothing is fixed in its code.
        5. Cross-check. For sources marked ✓ below, Forge's own trusted reference reads the same values from the source (a temperature, a rate, today's headlines, Wikipedia's summary); the answer must match them. Anything that fails is repaired and retried, up to 4 attempts, or it is not kept.
        6. Answer, then your OK. The test ran on your own question, so you get that answer right away, with its source. Then you choose whether to keep the skill, after seeing every site it can reach. Keep it, and next time it's instant.

        Where real-time data comes from

        Every answer is fetched live from the source when you ask. A repeat within 10 minutes reuses the source's last reply; if a source is down, I say how old the answer is (2 hours at most). ✓ means its answers are cross-checked.
